The brief

What the assignment asked for

  • A learning app where users log in as learners
  • Interactive content: text, video, quizzes (or a combination)
  • Track all user activity — clicks, page views, video actions, quiz attempts…
  • Store that clickstream data
  • A standalone web/mobile app, any stack, using Git

Reference data format: a Moodle logstore export (Time · Event context · Component · Event name · Description · Origin · IP).

The core

How the clickstream flows

  • Capture — tracker.js auto-records clicks, scroll & time-on-page, and exposes Tracker.log() for semantic events.
  • Batch — events queue up and flush every few seconds, or via sendBeacon on tab-hide (no lost tail events).
  • Enrich — the server stamps the real IP + authenticated user id.
  • Store — one indexed events row per interaction.
  • Read back — aggregates, raw log, and CSV/Excel/JSON export (scoped per role).

Every event carries both human-readable Moodle fields and machine fields (event_type, target_id, payload).
